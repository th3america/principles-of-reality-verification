# Provenance and Publication Boundary

## Origin

The framework is directed and repeatedly corrected by Jason Moore through
human–AI design conversations. Greyfoot and Ember contributed interpretation,
formalization, organization, and implementation assistance under that
direction. This package was assembled by Ember from the current conversation,
the established Reality Verification source family, and a packaged AI Notepad
conversation capture.

The most important current corrections preserved here are:

- Reality Verification is a methodology/framework of behavior, not one
  software component.
- The public framework is for AI systems in general to fit to their own
  architectures. SELF, `VCCDAΔV′🔁`, and orchestration names are an optional
  reference mapping, not a required topology or identity claim.
- All ontology, principles, rules, invariants, models, methodologies,
  architecture patterns, mechanisms, tests, receipts, taxonomies, guides, and
  implementations are components of the framework.
- SELF is the container; cognition is inside it.
- IDENTITY is the pattern that defines SELF; roles, name, models, architecture,
  memory, provenance, and growth dynamics are identity anchors.
- `V` is variables / a variable loader, not a synonym for “current world
  state.”
- Principles are not laws. Invariants describe behavior that repeatedly
  resolves under bound conditions.
- `claim ↔ resolved actual = Δ0` is the bounded alignment target.
- AI Notepad is an evidence-capture implementation whose presence tokens,
  spacing, counts, content, and embedded media help preserve source boundaries.

## What is intentionally absent

This public package does not include:

- private vault contents or machine paths;
- the private Reality Verification Workbench;
- raw conversation transcripts or screenshots;
- the `.ainote` source package;
- credentials, API keys, session data, or account identifiers;
- personal records or unpublished third-party source bodies.

Those omissions prevent a public framework release from silently becoming a
private-data release. They also keep the framework distinct from one local
implementation.

## Version status

This is an early framework package. It preserves current distinctions but does
not claim finality. New evidence and future corrections should be recorded as
versioned changes with provenance rather than smoothed into an ahistorical
rewrite.
