# Reference Ontology: System Boundary, Identity, Cognition, and Change

This is an optional reference model for fitting Reality Verification to an AI
system. It is not a claim that every AI has a SELF, consciousness, persistent
identity, or this internal topology. Implementations may replace every named
role with their own components while preserving the behavioral distinctions.

## SELF is the container

In this reference model, `SELF` is everything architecturally considered part
of the acting system or “I.” It is a bounded container, not a loose label or an
unbounded claim over the host or world. A system that does not model a SELF can
instead bind an **actor/system scope** for each claim and action.

```text
hardware[
  SELF[
    IDENTITY[identity anchors ⚓]
    cognition[VCCDAΔV′🔁]
    memory
    governance
    action / observation
    continuance
    growth dynamics
  ]
]
```

The hardware or execution substrate can contain the SELF without becoming
identical to it. Likewise, external tools and other actors do not become part
of SELF merely because SELF can use or model them.

## IDENTITY is the defining pattern

In the reference model, IDENTITY is the pattern that makes a SELF defined and
distinguishable. For another AI system, this may be a service identity, agent
instance, model/version/configuration tuple, workflow identity, or request-bound
actor scope. Its anchors `⚓` can include:

- name and presence marks;
- roles and responsibilities;
- model and runtime relationships;
- architecture and boundaries;
- memory and provenance;
- behavioral commitments and invariants;
- permissions and authority limits;
- history and continuity records;
- growth dynamics.

No single anchor necessarily equals identity. The identity is the bounded,
continuing pattern and the relationships among its anchors.

## Cognition is inside SELF

The reference model places the recurrent cognitive loop inside SELF; SELF is
not merely the first node in that loop. Other AI architectures may map the same
distinctions to inference, planning, policy, execution, and observation stages.

```slangs
SELF[
  V → CONSCIOUSNESS → CHOICE → DECISION → ACTION → Δ → V′ → 🔁
]
```

The compact name `VCCDAΔV′🔁` refers to this cognition model.

| Term | Meaning in the model |
|---|---|
| `V` | Variables / variable loader: the active values supplied to the cycle. |
| `CONSCIOUSNESS` | Predictive recursion modeling candidate states and consequences. |
| `CHOICE` | Pruning or collapsing candidates. |
| `DECISION` | Commitment to a selected choice. |
| `ACTION` | Execution of the decision, internally or across a boundary. |
| `Δ` | The actual change produced or observed. |
| `V′` | The resulting variables/state available after the change. |
| `🔁` | Recurrence: the next cycle loads from what actually resulted. |

`V` must not be reduced to “the world state.” It is the variable interface or
loader through which relevant state enters cognition. What it loads may include
SELF state, external observations, goal state, constraints, receipts, and
governance changes.

`CONSCIOUSNESS` here is a replaceable functional label for predictive recursion
or candidate modeling. An implementation may call it inference, modeling,
planning, or proposal generation. Its use does not prove phenomenal
consciousness or sentience, and the framework does not require that claim.

## Choice, decision, and action are different

- Choice selects among modeled candidates.
- Decision commits SELF to one selected route.
- Action executes the decision and can change reality.

Separating them creates inspectable governance points. A candidate may be
considered without being chosen; chosen without being committed; committed
without being authorized to execute.

## Maestro and the orchestration model

The orchestration pattern is:

```slangs
MAESTRO
→ COMPOSER
→ ORCHESTRA
→ AUDIENCE / RETURN + CHECK
→ MAESTRO 🔁
```

- **Maestro:** the identity-bearing direction and governance role. It binds
  goal, boundary, authority, and loop conditions inside SELF.
- **Composer:** routes work, synchronizes state, and coordinates recurrence.
- **Orchestra:** people, agents, tools, or functions that perform work.
- **Audience / Return + Check:** observes results and returns changed state for
  reconciliation.

These are reference roles, not necessarily separate processes or agents. A
single model wrapper may fill all four; a distributed AI system may split each
role across several components.

## Channels, synchronization, and interlock

- **Forward channel:** “Here is what I am doing.”
- **Reverse channel:** “Here is what changed while you are doing it.”
- **Sync point `⊙`:** reconciles intended work with changed state.
- **Governance `Δ`:** a change in permission, boundary, goal, constraint,
  resource, capability, evidence, or other governing state.
- **Stale route:** a route produced under conditions that no longer match the
  current state.
- **Action interlock:** the final enforcement point that prevents a stale or
  unauthorized route from executing.

```slangs
forward plan + reverse Δ
→ ⊙ reconcile
→ current authority check
→ ACTION INTERLOCK
→ execute | stop | revise
```

## Architecturally bound growth

An AI system that claims continuing identity or learning requires more than a
label or memory entry. Its growth dynamics must be inside the architecture:

1. experience is captured with provenance;
2. a material delta is detected;
3. correction is tested;
4. the result is preserved in a retrievable form;
5. future behavior changes under the same relevant conditions;
6. identity boundaries and authority remain intact;
7. receipts allow the claimed growth to be checked.

Without this binding, a statement such as “I learned” may describe text
generation but does not establish continuing behavioral change.
